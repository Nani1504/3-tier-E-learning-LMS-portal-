Overview

This system is a small but complete Learning Management System. Instructors create courses and upload lesson videos; students enroll, watch, and track their progress. It's built as three tiers so it can showcase the core Kubernetes building blocks — Deployments, Services, a StatefulSet with persistent storage, ConfigMaps and Secrets, health probes, an Ingress, and a Horizontal Pod Autoscaler.

Tier 1 · Presentation
React SPA served by nginx

Role-based UI for students and instructors. nginx also proxies /api to the backend so the browser talks to one origin.

Tier 2 · Application
Node.js + Express REST API

JWT auth, role-based access, courses/lessons, enrollments, progress, and video uploads. Stateless, so it can scale horizontally.

Tier 3 · Data
PostgreSQL + Amazon EFS

PostgreSQL is the system of record (persisted via a StatefulSet + PVC). Lesson videos live on an EFS file system every backend replica mounts (ReadWriteMany).

Architecture Request & data flow

Traffic enters through the Ingress. Page requests go to the frontend; the frontend proxies API calls to the backend; the backend reads/writes PostgreSQL and stores lesson videos on a shared Amazon EFS volume mounted at /data/videos in every replica (ReadWriteMany), streaming them back at /api/videos/…. The HPA watches the backend's CPU and adds replicas under load — each new pod mounts the same EFS volume.

Before you start What you'll need

Accounts

AWS account

With permissions for EKS, EC2, ECR, and IAM. A free-tier account works, but EKS itself isn't free — remember the teardown step.

Tools

CLIs installed

docker, kubectl, aws CLI v2, and eksctl on your machine. Step 1 checks each one.

Time

~45 minutes

Cluster creation is the long pole (~15–20 min). The deploy itself takes a couple of minutes.

Prefer to practise locally first? Every manifest here also runs on minikube or kind — the notes in Steps 3–4 tell you what changes. There's also a docker-compose.yml in the repo for a one-command local stack.

4

Install cluster add-ons

Four cluster capabilities are needed before the app will run correctly.

a) metrics-server — required for the HPA

Without it the autoscaler can't read CPU and shows <unknown>.

b) AWS Load Balancer Controller — turns the Ingress into a real ALB

Watches Ingress objects with ingressClassName: alb and provisions an Application Load Balancer that routes straight to the pod IPs, with TLS from ACM. It needs IAM permissions — classroom-simple: attach the policy to the node role (production would use IRSA / Pod Identity):

The ALB lands in subnets tagged kubernetes.io/role/elb=1 (eksctl tags its public subnets for you). HTTPS needs an ACM certificate in the same region that matches your domain — put its ARN in the alb.ingress.kubernetes.io/certificate-arn annotation in k8s/08-ingress.yaml. Our classroom cert covers awswithavinashreddy.com (apex only — no wildcard, so no subdomains).

c) EBS CSI driver — required for the PostgreSQL PVC

EKS needs this driver to turn the PostgreSQL PersistentVolumeClaim into a real EBS volume. Skip it and that pod sits in Pending forever.

d) Amazon EFS — shared video storage (file system + CSI driver)

Lesson videos live on an EFS file system that every backend replica mounts at the same time (ReadWriteMany — something a single-node EBS volume cannot do). One-time AWS setup: create the file system, give it a network path in each node AZ, then install the CSI driver that teaches Kubernetes how to mount it.

Finally, put your <FS_ID> in the fileSystemId parameter of the efs-sc StorageClass in k8s/04-efs-storage.yaml (and k8s/full-deploy.yaml if you deploy from the single file).

A mount target is the per-AZ network endpoint (ENI) pods use to reach EFS over NFS; the security group on it must allow port 2049 from the VPC. With provisioningMode: efs-ap in the StorageClass, the CSI driver auto-creates an EFS Access Point per PVC — no manual PV needed. For the full classroom walkthrough see the "EKS + EFS: Shared Storage" guide.

On minikube/kind these add-ons differ: run minikube addons enable metrics-server ingress, storage/PVCs work out of the box — and there is no EFS or ALB: see the note in k8s/04-efs-storage.yaml for swapping the video claim to a local ReadWriteOnce volume, and change the Ingress to ingressClassName: nginx (drop the alb.* annotations) to use minikube's ingress add-on instead.

6

Review configuration and secrets

Open k8s/full-deploy.yaml and set values appropriate for your environment before deploying. At minimum:

  • Change JWT_SECRET and the database passwords in the Secret blocks.
  • Set fileSystemId in the efs-sc StorageClass to your EFS file system id from Step 4d — the claim can't bind without it.
  • If you ran the ECR script, verify the two image: lines now point at your ECR registry.

Keep the two sides in sync: the DB user/password appears in both lms-secrets (what the API uses) and postgres-secrets (what Postgres is created with). If they drift, the backend can't connect and crash-loops.

Reference Components & manifests, in deploy order

Each block below is one component of the system, in the exact order it's applied. The brief explains what it is and why it matters; the code is the actual manifest from the repo's k8s/ folder. Applying 00 → 08 in sequence is identical to applying the single full-deploy.yaml.

00Namespacelms

A namespace is a logical partition inside the cluster. Every other object in this project declares namespace: lms, so this must be created first. It lets you list, manage, and delete the whole app as one unit and scope RBAC and quotas to it.

  • Created before anything else — the rest of the manifest lives inside it.
  • Delete it and every LMS object goes with it (clean teardown).
01ConfigMapslms-config + lms-db-init

Two ConfigMaps hold non-secret configuration. lms-config feeds the backend its runtime settings (ports, DB host/name, the video storage path, CORS) as environment variables via envFrom. lms-db-init carries the SQL schema and demo seed data, mounted into Postgres so tables and demo accounts are created on first boot.

  • Change app behaviour without rebuilding the image.
  • VIDEO_DATA_DIR must match the path the EFS volume is mounted at in the backend Deployment (/data/videos).
  • The init SQL runs only on an empty database (first start).
02Secretslms-secrets + postgres-secrets

Sensitive values kept out of ConfigMaps and images: the JWT signing key and the database username/password the app uses. Postgres reads its own secret for bootstrap credentials. Written as stringData here for readability; Kubernetes stores them base64-encoded.

  • The DB credentials in lms-secrets must match postgres-secrets.
  • For real use, replace with a sealed-secrets controller, SOPS, or an external secret store.
03PostgreSQLStatefulSet + headless Service + PVC

The system of record. A StatefulSet gives the pod a stable identity (postgres-0) and, through volumeClaimTemplates, a PersistentVolumeClaim whose data survives pod restarts and rescheduling. The headless Service (clusterIP: None) gives it a stable in-cluster DNS name. This is the persistence showcase.

  • Deploy before the backend — the backend's readiness probe waits on the DB.
  • PVC keeps data when the pod is deleted or moved.
  • On EKS this needs the EBS CSI driver + a default StorageClass (see Step 4).
04EFS shared video storageStorageClass + ReadWriteMany PVC

Shared storage for lesson videos on Amazon EFS. The StorageClass points the EFS CSI driver at your file system with provisioningMode: efs-ap — when the PVC arrives, the driver auto-creates an EFS Access Point (an isolated directory) for it, no manual PV needed. The claim is ReadWriteMany: every backend replica, on any node, mounts it at the same time.

  • RWX is the point — a Deployment's pods land on different nodes, and they all need the same files. EBS can't do that; EFS can.
  • Set fileSystemId to your file system from Step 4d.
  • The 5Gi request satisfies the API; EFS itself is elastic and unenforced.
05Backend APIDeployment + Service

The Node.js/Express REST API — 2 replicas to start. It reads plain config from lms-config and secrets from lms-secrets with envFrom, and mounts the shared EFS claim at /data/videos — where uploads land and videos are streamed from at /api/videos/…. Liveness hits /healthz; readiness hits /readyz, which checks the database connection.

  • App state lives in Postgres and on EFS, so the HPA can add and remove replicas freely.
  • The RWX volume means every replica — current or newly scaled — serves the same videos.
  • The ClusterIP Service backend:4000 load-balances across replicas.
  • Set the real image here (or let the ECR script rewrite it).
06Horizontal Pod Autoscalerbackend-hpa

The autoscaling showcase. The HPA scales the backend from 2 up to 10 replicas when average CPU crosses 60%, then scales back down once load subsides. Its behaviour is tuned for a quick scale-up and a gentle scale-down.

  • Requires metrics-server in the cluster (Step 4).
  • Reads CPU against the backend's resource requests.
  • Watch it react live under load in Step 9.
07Frontend SPADeployment + Service

nginx serving the built React single-page app — 2 replicas. nginx also reverse-proxies /api to the backend Service, so the browser only ever talks to one origin. The BACKEND_URL env var tells nginx where the API lives. Health is served at /healthz.

  • Runs as a non-root nginx image on port 8080.
  • The Service maps port 80 → container 8080.
  • Deploy after the backend so the proxy target exists.
08Ingress (AWS ALB)lms-ingress

The single public entry point. The AWS Load Balancer Controller reads this object and provisions a real Application Load Balancer that routes straight to the frontend pod IPs (target-type: ip); the frontend proxies /api (including video streaming at /api/videos/…) to the backend. TLS terminates at the ALB with the ACM certificate, and plain HTTP is redirected to HTTPS.

  • Requires the AWS Load Balancer Controller (Step 4b) and an ACM cert matching the host.
  • idle_timeout.timeout_seconds=300 keeps slow 500MB uploads alive (default is 60s).
  • One host covers everything — videos are served by the backend from EFS, so no second hostname is needed.
  • Deleting the Ingress deletes the ALB (clean teardown).

Help Troubleshooting

The issues students hit most often, and how to clear them.

Pods stuck in Pending
Likely cause: Usually no schedulable node or an unbound PVC.
Fix: kubectl describe pod <name> -n lms. If it's the PVC, install the EBS CSI driver and confirm a default StorageClass exists (Step 4c). If it's scheduling, check kubectl get nodes.
ImagePullBackOff / ErrImagePull
Likely cause: The node can't pull the image.
Fix: Verify the image: URI matches what you pushed, that the ECR repo exists, and that the node IAM role allows ECR pulls (eksctl managed nodes get this by default). Re-run the ECR script if unsure.
HPA shows TARGETS <unknown>
Likely cause: metrics-server isn't running.
Fix: Install it (Step 4a) and wait a minute for metrics to populate: kubectl top pods -n lms should return numbers.
Ingress ADDRESS is empty
Likely cause: The ALB controller isn't running, lacks IAM permissions, or can't find tagged subnets.
Fix: kubectl logs -n kube-system deploy/aws-load-balancer-controller shows the exact error. Check the controller pods are Running, the AWSLoadBalancerControllerIAMPolicy is attached to the node role (Step 4b), public subnets carry kubernetes.io/role/elb=1, and the certificate ARN in the Ingress is valid. A new ALB also takes ~2–3 min to go active.
PVC lms-videos stuck Pending
Likely cause: EFS CSI driver missing, or the StorageClass points at the wrong file system.
Fix: Confirm the add-on is ACTIVE (kubectl get pods -n kube-system -l app.kubernetes.io/name=aws-efs-csi-driver) and that fileSystemId in the efs-sc StorageClass is your FS id. kubectl describe pvc lms-videos -n lms shows the provisioner error.
Backend stuck ContainerCreating (mount timeout)
Likely cause: Pods can't reach EFS over NFS — almost always the security group or a missing mount target.
Fix: A mount target must exist (state available) in every AZ the nodes run in, and its security group must allow TCP 2049 from the VPC CIDR. kubectl describe pod shows the mount error in Events.
Video won't play
Likely cause: The upload never landed on the volume, or the backend can't read it.
Fix: kubectl exec deploy/backend -n lms -- find /data/videos/lessons -type f — if the file is there, check kubectl logs deploy/backend -n lms; if not, re-upload and watch the logs for write errors on the mount.
Backend CrashLoopBackOff
Likely cause: Most often a DB credential mismatch.
Fix: Check kubectl logs deploy/backend -n lms. Ensure the DB user/password match between lms-secrets and postgres-secrets, and that postgres-0 is Ready.
